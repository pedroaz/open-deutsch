# Domain

This package owns deterministic learning behavior shared by Electron and MCP entry points. It must not depend on either application shell.

The learner profile uses A1–B2 only for approximate calibration, never certification. Optional diagnostic provenance is explicit; inferred strengths and weaknesses preserve their source while recording learner edits. UI locale (English initially, then EN/DE) and teaching/explanation language are independent fields.

Model preferences are stored independently for correction, generation, helper, and research workloads. The runtime catalog is narrowed to the available GPT-5.6 Sol, Terra, and Luna entries and to `low`, `medium`, `high`, and `xhigh` effort. Automatic model selection follows the runtime default. Fast prefers `low` and then the model default; Balanced uses the model default; Deep prefers `high`, then the closest supported ordinary effort, and finally the model default. Maximum, Ultra, and pro modes are never selectable. A disappeared exact choice is not silently rewritten: the preference remains the authoritative saved identifier, while runtime resolution identifies which saved selector is unavailable and exposes a visible temporary fallback. If no runtime default model or supported effort exists, resolution is unavailable rather than guessed.

AI-generated exercises use one of the six accepted deterministic formats, each correlated with its own answer contract and immediate or submit-at-end feedback mode. Multi-part answers use stable zero-based snapshot positions rather than forgeable or duplicate generated keys. Custom, curriculum-topic, and vocabulary-set lessons carry bounded AI provenance, A1–B2 calibration, objectives, explanation/content, curriculum and vocabulary-set links, and complete exercise definitions. A generated artifact is ephemeral; only the separate `started` snapshot shape is eligible for persistence. Completion and abandonment belong to attempt contracts rather than mutating lesson content, and the snapshot is self-contained so History never depends on retained Codex task context.

Attempts preserve one canonical start instant plus a causal chain of nonnegative answer/terminal timing offsets, and use separate in-progress, completed, and abandoned shapes. Each interaction embeds its immutable exercise definition and accepts only the matching answer kind; completion requires at least one answer, qualitative positional objective evidence, bounded open feedback, and uncertainty. It never produces a certification or one-dimensional mastery score. Feedback may link opaque mistake and vocabulary-candidate identifiers, but it cannot carry raw model rationale or arbitrary detail.

Corrections store an ordered alignment as the sole authority for both original and corrected text, avoiding contradictory duplicate text/spans. Replacement, insertion, deletion, and unchanged segments support inline and side-by-side reconstruction; every change carries category, severity, priority, concise explanation, grammar-topic links, and uncertainty. Natural alternatives, vocabulary candidates, and targeted follow-up suggestions are explicit bounded states, and candidates never enter active vocabulary automatically.

Generated Draft 2020-12 correction schemas provide closed structural prevalidation. Replacement inequality is a deliberate cross-field runtime invariant that JSON Schema cannot express: every AI, IPC, or persistence consumer must still parse the value with `correctionSchema` before treating it as an accepted correction.

Mistakes retain bounded correction evidence grouped by a grammar or vocabulary category and calendar date. A single occurrence is explicitly distinct from a recurring pattern; recurrence requires at least two distinct correction-segment references. Learner amendments preserve the inferred category, dismissal retains auditable evidence, and deletion is a separate minimal command because successfully deleted evidence must not remain in a record. Targeted practice links an activity without rewriting the source evidence. Duplicate-reference and no-op-amendment checks are runtime cross-field invariants, so accepting boundaries must parse with `mistakeSchema` after JSON Schema structural prevalidation.

Vocabulary entries keep lemma, meaning, source context, examples, and part-of-speech-specific forms together. German noun gender and article are structurally correlated, while plural applicability is explicit. Candidate entries always require learner confirmation and cannot carry review state; active and suspended entries record when confirmation occurred and retain a simple five-stage schedule. Reviews are optimistic transitions from a complete expected active-state snapshot, so candidate and suspended cards cannot produce grades or scheduling metadata. They use the bounded Again/Hard/Good/Easy grades without duplicating the authoritative review event. Confirmation, due-date, review, and suspension chronology rules are runtime cross-field invariants, so accepting boundaries must parse with the domain schema after JSON Schema structural prevalidation.

Weekly plans are explicitly advisory, on-demand artifacts. Each goal owns its suggested activities and bounded curriculum/mistake/vocabulary context, so no generated key or cross-list position is needed to associate a suggestion with its goal. Suggestions are natural requests, not started activities: the contract deliberately has no completion checkbox, attempt/activity link, completion timestamp, or automatic reconciliation state. Creating a replacement plan does not mutate activity history, and completing an activity does not mutate the stored plan.

Voice history stores only an explicit bounded session summary: scenario/topic/goals, optional known duration, categorized observations, vocabulary notes, feedback, and natural-request next steps. Evidence is summarized rather than represented as timed transcript spans. The strict boundary has no audio, recording, transcript, token, or arbitrary provider-payload field; Open Deutsch neither requires nor accepts those artifacts to reconstruct the saved summary.

Curriculum topic front matter distinguishes incomplete foundations from foundation-ready records. Ready topics require grammar and vocabulary foundations, a lesson foundation, an exercise blueprint, sources, and at least one mapped CEFR reception/production/interaction/mediation outcome. The aggregate filesystem validator—not either YAML schema alone—is authoritative for unique manifest paths/IDs, nonempty Markdown bodies, path/front-matter agreement, prerequisite graphs, and source references. Generated Draft 2020-12 source-registry schemas are structural prevalidation: retrieval/review/due-date ordering is a documented runtime cross-field invariant, so accepting boundaries and filesystem validation must still parse with `curriculumSourceRegistrySchema`.
